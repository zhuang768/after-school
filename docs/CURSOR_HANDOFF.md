# Cursor 開發交接

使用者已指定：Cursor 負責完整開發，Codex 只擔任總監工與品質驗收官。唯一功能驗收依據為 [ORIGINAL_PROMPT.md](./ORIGINAL_PROMPT.md) 的 14 章，P0 的 13 項全部必須完整可用。

## 開工前

1. 完整閱讀原始需求與專案 AGENTS.md，先檢查目前檔案，再列出短計畫。
2. 列出你在本次環境實際可用的 skill、工具、MCP，說明前端、設計、測試、無障礙、資安與文件分別會使用什麼。相關工具沒使用時說明理由。不可假稱使用不存在或未執行的工具。
3. 現有檔案是先前 Codex 開發中途停止的部分骨架，不是已通過的完整實作。可修正或替換有問題的骨架，保留無關使用者資料。沒有任何先前測試結果可以沿用為通過。
4. 先前曾同時執行兩個 npm install，其中一個成功但另一個因 ENOTEMPTY 失敗。請自行檢查 package.json、lockfile 與依賴狀態，循序安裝及修復。eslint 9 的安裝曾回報已停止支援；零警告門檻不可忽略。不要直接把不完整 node_modules 視為可用。

## 開發與交付

- 小決定自主完成並記錄，真正無法繼續才提出一個精簡問題。產品、提示、README、隱私說明與範本均為英文；進度回報及 RESEARCH.md / DESIGN.md / DECISIONS.md / TEST_REPORT.md 以繁體中文。
- 開發、官方文件查證和合成資料測試可以使用網路。產品執行期間不得向外傳輸任何使用者資料，不得使用 OAuth、分析、追蹤、廣告或第三方腳本。
- 服務目錄至少 40 筆，所有提供的操作步驟必須逐項實際閱讀官方來源。沒有證據的欄位標 Unverified，不可捏造。政策因校而異，務必標來源與最後確認日期。
- 完整支援串流 Worker 解析大型 mbox、批次 eml、ZIP 防護、六種分類與學校收件者/轉寄篩選。不得用整檔讀入冒充串流。
- 完成全部 P0，再視品質與時間處理 P1/P2。不得刪除 P0 功能、測試或服務資料以製造通過。
- 以合成資料實測分類準確率與召回率、數百 MB 以上大型信箱、壓縮炸彈與惡意 HTML；記錄真實數據。
- 實際執行格式、lint、型別、單元、整合、建置、端到端與隱私網路監看；測試 production build。零警告交付。無法執行的項目標「未實際執行」並列出原因與待使用者驗證清單。
- Delete all my data 必須實際驗證 IndexedDB、localStorage、sessionStorage、Cache Storage、Service Worker 的清除。不得在清除後立刻自動寫回個人資料。
- .ics 需格式與提醒驗證；若沒有真正在 Google、Apple、Outlook 匯入並觀察提醒，就不可宣稱三者實測通過。螢幕閱讀器與實體行動瀏覽器亦同。
- 完成後完整回報：變更、所有驗證命令及結果、測試與量測證據路徑、未實測項目、已知限制。使用者後續會由 Codex 進行獨立全面驗收與最多 8 輪修正。

## 發布限制

可以做本機 Git 提交，但不要推送 GitHub、建立遠端 repo、發布、部署或變更外部帳號。本專案還沒有 Git remote。網域與是否公開上線均由使用者最終決定，需明確核准。先完成可審查的本機版本及部署設定。

## 完成訊號

真正完成後，請在最終聊天回覆與 docs/CURSOR_STATUS.md 記錄 `READY_FOR_ACCEPTANCE`、時間、目前 commit（若有）、可執行驗證命令與證據位置。若有尚未完成的 P0 或外部阻礙，明確記錄 `BLOCKED` 或 `INCOMPLETE`，不得寫成全部完成。沒有完成訊號或檔案仍變動時，Codex 不會介入驗收。
